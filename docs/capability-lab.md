# Images 2.5・sprite-gen能力実験

2026年9月10日。旧Dotterの骨格処理を通さず、Images 2.5で生成し、sprite-genで抽出・加工した。モデル指定は `gpt-image-2.5-sunburst`。画像生成11件、同じ画像の加工比較4件、合計15条件。各条件は1回の試行であり、品質の安定性や成功率までは測っていない。

人物は採用済みの細身のスーツ姿を参照画像として送信。狼・ドラゴンのモーションと荒廃背景には、それぞれ生成直後の基準画像を送信した。加工後の劣化した画像を参照にはしていない。モーション生成にはsprite-genの配置ガイドも送信している。

## 判定の範囲

原画・加工後のコマ一覧・単体画像を目視した。比較画面は1280pxと390pxのブラウザーで15件、画像読み込み失敗0、横はみ出し0、JavaScript例外0を確認。走りの再生画像が時間経過で変わることも確認した。全モーションをゲーム内で操作して滑らかさや攻撃感を評価したわけではない。

高速攻撃のGIFは4コマ・各50ミリ秒。2コマ目に発砲するため開始から50ミリ秒、60fps換算3フレーム。狼のGIFは各80ミリ秒、ドラゴンは各120ミリ秒で、指定fpsからGIFの時間単位へ丸められている。

背景は縮小せず32色へ減色した。元画像の大きさは1586×992。人物64、狼32、ドラゴン128は加工後のセルサイズであり、その解像度へ直接描けたことを意味しない。減色は画像全体の統計による処理で、目・ネクタイ・看板など重要部位の色を優先していない。

## 次に改善する順番

1. ジャンプの上下移動を保持し、全コマで共通の縮尺・基準点を使う抽出にする。切り出し成功でも軌道を壊す現状を先に直す。
2. 指定ドット数への適合と重要な顔・手・脚の可読性を分けて検査する。格子検出や縮小の警告を品質合格にしない。
3. 色を一括で削るだけでなく、顔・衣装・看板などのアクセントを残せるパレットにする。
4. 主要姿勢から完成モーションへ進む際に、左右交代、銃と手の連続性、戻りコマ、停止時間を編集できるようにする。

## 保存と再実行

素材はローカルの `assets/capability-lab/` に保存。各生成の `generation.json` にプロンプト・参照画像の記録・API使用量があり、`results.json` に評価と実測値がある。比較画面はTailscaleの http://100.103.94.8:4322/ 。素材と認証情報はGitへ含めない。

`run_capability_lab.py --stage initial` と `--stage dependent` は有料の画像生成を実行する。初期段階が終わってから依存段階を実行する。既存のraw.pngは保持してスキップする。両段階と加工比較を同時に実行すると一覧の書き込みが競合するため、順番に実行する。新しい実験では既存素材を削除せず、別の保存先・条件名を用意する。

`compare_lab_processing.py` はAPIを呼ばず4条件を加工比較する。`build_capability_gallery.py` が比較ページを作り、`serve_capability_lab.py --host 100.103.94.8 --port 4322` が素材ディレクトリだけを配信する。新規環境では採用画像 `assets/inputs/adopted-green-x8.png` を別途用意する必要がある。
