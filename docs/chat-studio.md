# 自然言語で制作するチャット

Orca経由のClaude Sonnetが依頼・会話履歴・参照画像・現在の再生順を確認して制作方針を組み立て、Images 2.5で生成する。生成結果を見ながら、次の依頼で画像やモーションを修正する。

## 開発環境と起動

Python 3.10以上、Orca CLI、Orcaから利用できるClaudeのログイン、画像生成用のOpenAI APIキーを用意する。以下はPython 3.13で開発する例。リポジトリのルートで依存関係を入れる。

```sh
uv venv --python 3.13
uv pip install --python .venv/bin/python -e '.[dev]'
```

`.env.local` に `OPENAI_API_KEY` を設定する。このファイルはGitに含めない。起動時に作業ディレクトリの `.env.local` を自動で読み込む。既に環境変数として設定してある値が優先される。

```sh
.venv/bin/sprite-studio --data-dir data --host 127.0.0.1 --port 4323
```

ブラウザーで http://127.0.0.1:4323/ を開く。会話担当はClaudeの `sonnet`、画像担当は `gpt-image-2.5-sunburst`。ClaudeはSDKではなくOrcaの端末で起動する。画像APIの秘密情報をブラウザーやSonnetのプロンプトへ渡さない。

### Orcaの対象

既定では起動時の作業ディレクトリをOrcaの対象にする。別のチェックアウトを使う場合は `--workspace /path/to/checkout` を指定する。Orcaの対象識別子を直接指定する場合は `--orca-worktree <selector>` を使う。Orcaで対象を開き、`orca status --json` で接続状態を確認する。

### Tailscaleから利用する

待受アドレスを端末のTailscale IPにして起動する。

```sh
.venv/bin/sprite-studio --data-dir data --host <Tailscale-IP> --port 4323
```

同じTailscaleネットワークのブラウザーから、そのIPの4323番ポートへアクセスする。個人利用向けで、ユーザー別認証は追加していない。

## 保存先とバックアップ

ソースコードと制作データは分けて保存する。`--data-dir` の既定値は `data`。別の場所を指定するときは絶対パスにすると起動場所に左右されない。

| 保存先 | 内容 |
|---|---|
| `data/library/index.json` | 参照素材の一覧 |
| `data/chat-studio/` | 個別の会話、制作の版、元画像、生成指示、生成報告と加工結果 |
| `.env.local` | 画像APIの認証設定 |

制作データと認証情報はGitの管理対象にしない。バックアップはアプリを停止してからデータディレクトリ全体をコピーする。別の環境ではバックアップを戻し、同じ保存先を `--data-dir` で指定する。秘密情報は別途設定する。

会話は個別保存し、制作のたびに新しい版を追加する。元画像と過去の版を上書きしない。失敗した場合も既に生成された画像は保持する。中断や失敗から有料生成を自動で再試行しない。

## 制作の流れ

1. 「新しくつくる」から新規制作を始めるか、登録済みの参照素材を選ぶ。素材名が依頼から分かる場合はSonnetが一覧から選ぶため、ディレクトリ指定は不要。
2. Sonnetへ元絵の実画像、直近の作品、会話履歴、素材の情報、コマ数・現在の再生順を渡す。必要なら外部資料を調査し、利用した資料のURLを保存する。
3. 特徴の整理と生成指示を表示し、画像生成・中間コマの追加・再生順と停止コマの調整・説明のいずれかを実行する。
4. Images 2.5に実際に送信したプロンプトと参照画像、生成報告を保存する。再生順に従ってGIFとコマ一覧を作る。
5. Sonnetが参照元と生成結果を画像として比較し、問題点を表示する。これはモデルによる静止画比較であり、人間の評価や実際の再生確認の代わりではない。

「4コマ目と5コマ目の間を描き足して」「今の順番のまま先頭を3コマ分止めて」「この顔と頭身を保ったまま走らせて」などを依頼できる。停止コマの複製と並べ替えでは画像APIを呼ばない。

## 現在の制限

- 1種類のモーションずつ修正する。中間コマの指定対象は元の横並び画像のコマであり、追加済みの中間コマを端点にした再補間は未対応。
- 再生順は0始まりで内部管理し、利用者の「4コマ目」などの表現をSonnetが変換する。実行前に範囲と隣接を検査する。
- 生成品質や指定解像度への直接描画は保証しない。抽出・縮小・減色による劣化が残る。生成後の比較で問題を表示し、次の依頼で修正する。
- バージョン選択は閲覧用。継続の制作対象は最新の版。自動品質修復を無制限には繰り返さない。
- 静的配信の対象は画面と素材画像のみ。会話・生成報告等のJSONは静的配信せず、操作用のAPIを使う。同一接続元のJSONリクエストだけを受け付ける。

## 開発時の確認

```sh
.venv/bin/python -m pytest tests/serve tests/docs
```

画像生成のテストでは通信を置き換える。有料の画像生成やOrca実接続は、このテストとは別に確認する。変更時には会話の分離、過去の版の保持、時間調整による不要な画像生成がないこと、スマホでの操作と画像表示を確認する。自動検査が通ったことだけで絵やモーションを品質合格にしない。


## 画面の操作確認

PCは中央の作品と右側の会話を並べて使う。スマホは会話内の作品をタップすると大きく表示できる。制作状況はどちらの画面にも表示され、「経過」から詳細を確認できる。
会話ごとの下書きは、このブラウザー内に保存する。過去の版は比較用に表示でき、修正依頼を送るには最新版へ戻る。

画面の回帰テストはNode.jsとPlaywrightを使い、5種類の画面幅で下書き・版選択・進捗・通信失敗・拡大操作を確認する。検証用サーバーと差し替えたAPIだけを使い、作品の生成や実データの変更は行わない。

```sh
npm install --prefix /tmp/sprite-ui-tests playwright
/tmp/sprite-ui-tests/node_modules/.bin/playwright install chromium
NODE_PATH=/tmp/sprite-ui-tests/node_modules node tests/browser/chat_studio.mjs
```

既存のChromeを使う場合は `SPRITE_TEST_CHROME` に実行ファイルのパスを指定する。実機のSafariとソフトウェアキーボードの挙動は、別途端末で確認する。
