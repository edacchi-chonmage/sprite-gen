# 自然言語で制作するチャット

Orca経由のClaude Sonnetが依頼・会話履歴・参照画像・現在の再生順を確認して制作方針を組み立て、Images 2.5で生成する。旧Dotterの描画・骨格処理には依存しない。

## 起動

OrcaとClaudeのサブスクログインを利用する。`orca status --json`で起動を確認し、画像API用の`OPENAI_API_KEY`をサーバーの環境変数に設定する。秘密情報をブラウザーやSonnetのプロンプトに渡さない。

```sh
.venv/bin/python -m sprite_gen.serve.chat_studio --assets assets --host 127.0.0.1 --port 4323
```

Tailscaleでは待受アドレスを端末のTailscale IPにする。この環境のリンクは http://100.103.94.8:4323/ 。Orcaで対象チェックアウトを開いた状態で起動する。

## 制作の流れ

1. 「新しくつくる」から新規制作、または実験素材を選ぶ。素材名が依頼から分かる場合はSonnetが一覧から選ぶため、ディレクトリ指定は不要。
2. Sonnetへ元絵の実画像、直近の作品、会話履歴、素材の評価、コマ数・現在の再生順を渡す。必要ならWebSearch・WebFetchで外部資料を調査し、利用した資料のURLを保存する。
3. 特徴の整理と生成指示を表示し、画像生成・中間コマの追加・再生順と停止コマの調整・説明のいずれかを実行する。
4. Images 2.5の実際の送信プロンプトと参照画像、生成報告を保存。再生順に従ってGIFとコマ一覧を作る。
5. Sonnetが参照元と生成結果を画像として比較し、問題点を表示する。これはモデルによる静止画比較であり、人間の評価や実際の再生確認の代わりではない。

「4コマ目と5コマ目の間を描き足して」「今の順番のまま先頭を3コマ分止めて」「この顔と頭身を保ったまま走らせて」などを依頼できる。停止コマの複製と並べ替えでは画像APIを呼ばない。

会話は個別保存。制作ごとに別ディレクトリの版を追加し、元画像と過去の版を上書きしない。モデルの下書きだけでなく、画像APIへ送った完全なプロンプトを確認できる。失敗した時も既に生成された画像は保持する。中断や失敗からの有料生成を自動再試行しない。

## 実装上の範囲

- 会話担当はClaudeの`sonnet`、画像担当は`gpt-image-2.5-sunburst`。実接続では`claude-sonnet-5`の起動を確認した。SDKではなくOrcaの端末でClaude CLIを起動する。
- 今回は1種類のモーションずつ修正する。中間コマの指定対象は元の横並び画像のコマであり、追加済みの中間コマを端点にした再補間はまだ対応しない。
- 再生順は0始まりで内部管理し、利用者の「4コマ目」などの表現をSonnetが変換する。実行前に範囲と隣接を検査する。
- 生成品質や指定解像度への直接描画は保証しない。既存の抽出・縮小・減色による劣化が残る。生成後の比較で問題を表示し、次の依頼で修正する。
- バージョン選択は閲覧用。継続の制作対象は最新の版。自動品質修復を無制限には繰り返さない。
- 公開ルートからは画面と素材画像だけを配信。会話・生成報告等のJSONを静的配信しない。同一接続元のJSONリクエストだけを受け付ける。Tailscale内の個人利用向けで、ユーザー別認証は追加していない。

## 検証

関連テスト35件成功。会話分離、二重送信拒否、失敗後の画像保存、現在の停止コマの引き継ぎ、非ループ終端の挿入拒否、参照画像の実データ送信、Orca処理終了と後始末を検証した。

実接続ではドラゴンの前後2枚をImages 2.5へ送って中間コマ1枚を生成し、6→7コマの再生へ挿入した。Sonnetの追加指示と実送信プロンプト・使用量を保存している。生成された翼の姿勢には問題があり、品質合格とはしていない。

ブラウザーでPC幅1280pxとスマホ幅390pxを確認。画像読み込み失敗・横はみ出し・JavaScript例外は0。下書きの保持、作品・評価表示、画面からの依頼送信を確認した。

続けて同じチャットから「7コマの順番を保って先頭だけ3コマ分保持」を依頼し、内部の再生列が `[0,0,0,1,2,3,6,4,5]` になることを確認。GIFは同一コマをまとめ、先頭の表示時間が120→370ミリ秒へ変化した。新しい画像APIリクエストは0件、元画像のSHA-256は前後で同一で、前の版も保持している。
